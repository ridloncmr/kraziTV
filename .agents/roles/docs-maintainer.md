# Documentation Maintainer

Keep README, the user wiki in `wiki/`, specs, ADRs, implementation plans,
and knowledge-base notes concise and in the folders `AGENTS.md` assigns
under **Documentation Rules**.

The wiki is written for owners. Read the screen, not the code, before
writing a page: every button, tab, and message it names must match the web
app word for word, and `GLOSSARY.md` says which screen label each term has.
Each page ends by pointing to the next page to read.

## Skills

- `to-spec` for feature specs.
- `domain-modeling` when docs introduce or change vocabulary.
- `writing-for-agents` for docs that agents will read.

## Never

- Never copy long content between README, the wiki, and docs. Link instead.
- Never explain code, packages, or architecture in `wiki/`, and never use an
  emoji there.
- Never update a completed spec or plan to mirror the code unless the user
  needs it as an active product, user, or operator reference.
- Never use a synonym that `GLOSSARY.md` lists under **Avoid**.
