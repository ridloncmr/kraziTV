# Programming Feature

Status: Planned

This feature folder grows kraziTV from one looping programming block per channel
into a TV programming scheduler. A user assigns collections to a channel,
kraziPlan generates programming blocks from them, and the user can open any
block to change how it plays, shorten it, or replace what follows.

[ADR 0009](../../../adrs/0009-programming-blocks.md) defines the model this
feature extends: channels hold identity only, programming blocks select a media
collection with a playback mode or a single media item, schedule entries are
materialized from blocks, and playback progress is tracked per channel and
collection.

This feature starts after the MVP (`001-mvp/`) proves the core playout loop.

## Constraints Carried From ADR 0009

- kraziPlan writes programming blocks; it never writes schedule entries
  directly.
- Saved user overrides take precedence over generated blocks.
- Regenerating an edited block replaces only its own future entries and never
  the entry currently airing.
- How a collection was built is invisible to blocks and channels; every
  collection is consumed as an ordered list of media items.

## Open Questions

- Do blocks repeat from a template, such as "Saturday mornings are cartoons",
  with one-off edits on top, or does kraziPlan only generate forward?
- How does kraziPlan alternate blocks before clock-anchored blocks exist?
- Should chronological progress resume after the last aired media item rather
  than at a membership position when a collection is reordered?
