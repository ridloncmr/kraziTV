# Implementation Plan

This folder tracks build sequencing, milestones, and task breakdowns.

Ticket status lives only in each ticket's `**Status**` block, and spec status
only in each spec's `Status:` line. The plan list below and the progress table
at the top of each plan are generated from ticket Status blocks by
`npm run plan:status`; never edit them by hand.

## Tracking Ticket Status

1. Give each ticket a `### <PREFIX>-NNN: <title>` heading, such as
   `### SIG-012: ...`. The generator finds tickets only by this shape.
2. When a ticket's state changes, add or edit the `**Status**` block directly
   under its heading. The generator shows the block's first sentence:

   | First line of the Status block      | Shown as                       |
   | ----------------------------------- | ------------------------------ |
   | `Complete on 2026-10-02. Delivered` | `Complete on 2026-10-02`, done |
   | Any other text, such as `Blocked.`  | That sentence, not done        |
   | No Status block                     | `Open`                         |

3. Run `npm run plan:status` and commit the regenerated plan and this README
   with the change. A new plan gets its progress table on the first run.
4. CI runs `npm run plan:status:check`, which fails and names each stale file
   when a generated block no longer matches the ticket Status blocks. Fix it by
   running `npm run plan:status`.

## MVP Build Order

Each milestone links to the spec that owns its scope and status.

1. Scaffold the monorepo, server health endpoint, and Web UI shell:
   [spec 0001](../specs/features/001-mvp/specs/0001-bootstrap.md).
2. Build the production-intent `packages/signal` primitives and their automated
   lifecycle and fan-out suite, then run the Plex HDHomeRun compatibility spike
   through them: [plan 0006](0006-signal-packager.md), Phases 1 and 2.
3. Implement the local media catalog and SQLite persistence:
   [plan 0002](0002-media-catalog.md).
4. Implement channel and ordered media-collection configuration:
   [plan 0003](0003-channel-config.md).
5. Implement deterministic schedule generation and current channel state,
   including connection-pinned read snapshots and an interleaved two-connection
   regeneration test:
   [spec 0004](../specs/features/001-mvp/specs/0004-schedule-generation.md) and
   [spec 0005](../specs/features/001-mvp/specs/0005-playout-timeline.md).
6. Integrate the spike-tested `packages/signal` primitives with real channel
   authorization, channel state, selected playout, and administrative shutdown:
   [plan 0006](0006-signal-packager.md), Phase 3.
7. Expose Plex-compatible tuner, guide, and stream endpoints:
   [spec 0007](../specs/features/001-mvp/specs/0007-plex-adapter.md).
8. Complete the MVP Web Admin flow:
   [spec 0008](../specs/features/001-mvp/specs/0008-web-admin.md).
