# kraziTV Glossary

Canonical vocabulary for kraziTV. Use these terms in code, tests, specs, ADRs,
and agent output. When a term here conflicts with a name elsewhere, the term
here wins unless the code has deliberately moved on; in that case update this
file in the same change.

- Add a term when it becomes shared vocabulary across files, docs, or agents.
- Keep each definition to one or two sentences. Link to the ADR or spec that
  owns the detail instead of repeating it.
- List rejected synonyms under **Avoid** so they do not creep back in.
- Never record whether a term is built yet. Link the spec or ADR that owns it;
  that document's status line says whether the behavior exists.

## Core Architecture

| Term                       | Definition                                                                                                                                                                                                                                                                                                                                                             | Avoid                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------- |
| **kraziBrain**             | The scheduling and playout decision engine. Decides what plays, when it plays, and why. Lives in `packages/krazi-brain`.                                                                                                                                                                                                                                               | scheduler service, programming engine   |
| **kraziPlan**              | The automatic programming generator inside kraziBrain. Generates programming blocks from the collections assigned to a channel; never writes schedule entries directly. Its code belongs in `packages/krazi-brain/src/krazi-plan/`. See [ADR 0009](docs/adrs/0009-programming-blocks.md) and the [programming feature](docs/specs/features/002-programming/README.md). | auto-scheduler, programming plan        |
| **SignalPackager**         | The streaming and media normalization layer. Turns selected media into a continuous stream; owns FFmpeg command construction. See [ADR 0005](docs/adrs/0005-signal-packager-package-boundary.md).                                                                                                                                                                      | encoder, transcoder (for the component) |
| **Provider adapter**       | The Plex-, Jellyfin-, or Emby-specific layer that exposes channels, guide data, and stream URLs. Never carries stream bytes.                                                                                                                                                                                                                                           | integration, plugin, connector          |
| **Metadata provider**      | An external service kraziTV calls to look up content metadata, such as TMDB. Unlike a provider adapter it exposes nothing; only `packages/media` calls it. See [ADR 0013](docs/adrs/0013-metadata-provider-calls-and-stored-key.md).                                                                                                                                   | provider (alone), metadata source       |
| **Public base URL**        | The origin Plex reaches kraziTV at, set by `PUBLIC_BASE_URL`. Every absolute tuner, lineup, and stream URL is built on it; request `Host` headers never are. See [spec 0007](docs/specs/features/001-mvp/specs/0007-plex-adapter.md).                                                                                                                                  | host URL, server URL                    |
| **Channel stream worker**  | The runtime worker that owns one shared broadcast signal for a watched channel and fans it out to subscribers. Code name `ChannelWorker`. See [ADR 0008](docs/adrs/0008-shared-active-channel-stream-workers.md).                                                                                                                                                      | per-viewer session, stream session      |
| **Channel stream manager** | Owns the set of active channel stream workers; starts a worker on first subscriber and reuses it for later ones. Code name `ChannelStreamManager`.                                                                                                                                                                                                                     | worker pool                             |
| **Playout provider**       | The port a channel stream worker asks what is airing now and what airs next; kraziBrain's adapter implements it. Code name `PlayoutProvider`.                                                                                                                                                                                                                          |                                         |
| **Transition coordinator** | The port that commits a prepared transition only if it still matches the current schedule, or reports it stale. Code name `TransitionCoordinator`. See [ADR 0003](docs/adrs/0003-materialized-schedule-entries.md).                                                                                                                                                    |                                         |
| **Write authority**        | SQLite's single writer lock, taken with `BEGIN IMMEDIATE` before a schedule mutation reads state, so concurrent writers never act on stale reads. Taken by `runImmediateTransaction`.                                                                                                                                                                                  | write lock                              |
| **Schedule snapshot**      | A connection-pinned deferred read that reads `scheduleRevision` first and every other row through the same transaction, so one playout result never mixes revisions. Never writes; contrast with **Write authority**. Taken by `readPlayoutSnapshot`.                                                                                                                  |                                         |
| **Signal session**         | SignalPackager's running output for one channel stream worker: one stable MPEG-TS stream fed by successive FFmpeg processes, one per playout item. Code name `SignalSession`.                                                                                                                                                                                          | stream session, encoding session        |
| **Signal preparation**     | The next playout item's FFmpeg process, started ahead of its boundary with its output held, until the worker commits it at the boundary or discards it. Revocable and limited to one. Code name `SignalPreparation`. See [ADR 0016](docs/adrs/0016-prepared-ffmpeg-process.md).                                                                                        |                                         |
| **FFmpeg process**         | One FFmpeg child that encodes a single playout item for a signal session. Code name `FfmpegProcess`.                                                                                                                                                                                                                                                                   | encoder                                 |

## Programming And Playout

| Term                       | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                             | Avoid                             |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------- |
| **Channel**                | A configured, continuously broadcasting lineup position that viewers tune to. Holds identity only (number, name, enabled); its programming lives in programming blocks.                                                                                                                                                                                                                                                                                                | station, stream                   |
| **Channel number**         | A channel's unique, user-visible lineup number in canonical string form: a major number with an optional subchannel, such as `69` or `69.1`. Parsed and ordered by `parseChannelNumber` and `compareChannelNumbers` in the server.                                                                                                                                                                                                                                     | channel ID, position              |
| **Major number**           | The part of a channel number before the separator, such as `69` in `69.1`. A positive integer with no leading zeroes.                                                                                                                                                                                                                                                                                                                                                  | main number                       |
| **Subchannel**             | The optional part of a channel number after the separator, such as `1` in `69.1`. A positive integer with no leading zeroes; a number without one sorts before its subchannels.                                                                                                                                                                                                                                                                                        | minor number, sub-number          |
| **Programming block**      | One generated kraziPlan turn: the assignment member that took it, its resolved size, and the rotation checkpoint from before it. Schedule entries are generated from blocks, which stay as history like entries. See [ADR 0009](docs/adrs/0009-programming-blocks.md) and [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                        | slot, daypart, rule               |
| **Schedule**               | The guide-visible programming viewers see. Never includes things that are transmitted but not listed.                                                                                                                                                                                                                                                                                                                                                                  | playlist, timeline (for this)     |
| **Schedule entry**         | One persisted, guide-visible program on a channel's schedule. The authority for guide output. See [ADR 0003](docs/adrs/0003-materialized-schedule-entries.md).                                                                                                                                                                                                                                                                                                         | slot, listing                     |
| **Schedule anchor**        | The stable UTC millisecond at which a channel's schedule generation begins. Persisted as `anchorTime` in `ChannelScheduleState`.                                                                                                                                                                                                                                                                                                                                       | start time, epoch                 |
| **Coverage**               | The time through which a channel's schedule entries have been materialized. Reads that need a later instant extend coverage before answering. See [spec 0005](docs/specs/features/001-mvp/specs/0005-playout-timeline.md).                                                                                                                                                                                                                                             | generated window                  |
| **Horizon**                | How far into the future a channel's schedule entries are materialized. Horizon extension adds entries without rewriting covered windows.                                                                                                                                                                                                                                                                                                                               | lookahead, buffer                 |
| **Gap repair**             | An explicit, logged regeneration when an enabled channel's coverage has lapsed. Starts at the current time and leaves the uncovered interval empty. Planned filler is coverage, never a gap ([ADR 0014](docs/adrs/0014-planned-filler-coverage.md)).                                                                                                                                                                                                                   | backfill, auto-fix                |
| **Regeneration**           | Deleting and rebuilding future schedule entries after an input change. Never alters the playout item currently airing, program or filler, unless the user explicitly interrupts it ([ADR 0003](docs/adrs/0003-materialized-schedule-entries.md), [ADR 0014](docs/adrs/0014-planned-filler-coverage.md)).                                                                                                                                                               | reschedule, refresh               |
| **Regeneration boundary**  | Where regeneration starts: the end of the playout item currently airing, program or filler, or the current time when nothing is airing. Entries before it are kept.                                                                                                                                                                                                                                                                                                    | cutoff, split point               |
| **Schedule revision**      | A per-channel counter that increments once with every commit that changes the channel's planned transmission: its schedule entries, or a reservation that determines filler. No-op coverage checks leave it unchanged. Stored as `scheduleRevision`. See [ADR 0014](docs/adrs/0014-planned-filler-coverage.md).                                                                                                                                                        | version, generation               |
| **Configuration revision** | A per-channel counter that increments with every assignment, rule, or marathon-setting write that changes the channel's programming configuration. Previews report it so a stale one can be told apart; unlike the schedule revision it ignores generation. Stored as `configuration_revision`. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md).                                                            | config version                    |
| **Programming revision**   | A per-channel counter that increments with every commit that changes the planned programming a reservation preview shows: a regeneration, an interruption, or a reservation write. Unlike the schedule revision, coverage extension leaves it unchanged, so a reservation save carries it as its preview token. Stored as `programming_revision`. See [programming spec 0007](docs/specs/features/002-programming/specs/0007-manual-programming.md).                   | preview token, preview revision   |
| **Schedulable**            | Describes an available media item that meets the duration floor. A channel is schedulable when its programming block's source has at least one.                                                                                                                                                                                                                                                                                                                        | valid                             |
| **Playable**               | Describes media a channel can transmit: `available`, with a positive duration and a known audio fact. Unlike schedulable it has no duration floor; only playable entries become playout items. See [spec 0005](docs/specs/features/001-mvp/specs/0005-playout-timeline.md).                                                                                                                                                                                            | transmittable, valid              |
| **Playback mode**          | How a programming source assignment orders each of its media collections: `chronological` (saved collection order), `episode`, `release`, or `random` (deterministic, seeded). See [programming spec 0003](docs/specs/features/002-programming/specs/0003-playback-ordering.md).                                                                                                                                                                                       | shuffle mode                      |
| **Playback progress**      | How far a channel has advanced through one media collection in one playback mode: the last selected media item and its position for ordered modes, or the random selection index. Tracked per channel, collection, and mode, so separate blocks of the same collection and mode continue from each other ([ADR 0009](docs/adrs/0009-programming-blocks.md)).                                                                                                           | cursor, resume point              |
| **Ordered view**           | A collection's members in the order one playback mode plays them, computed by kraziBrain without changing saved membership; the block preview shows it with its unresolved, series-group, and duplicate flags. Random has none. See [programming spec 0003](docs/specs/features/002-programming/specs/0003-playback-ordering.md).                                                                                                                                      | sorted collection, resolved order |
| **Order fingerprint**      | A hash of an episode- or release-order ordered view that a channel's schedule was generated from. A metadata write regenerates only channels whose fingerprint changed. Stored as `order_fingerprint`. See [programming spec 0003](docs/specs/features/002-programming/specs/0003-playback-ordering.md).                                                                                                                                                               | order hash, checksum              |
| **Progress reset**         | The owner's confirmed restart of one channel's playback progress through one collection in one mode, applied after the airing entry; restoration never returns to progress from before it. See [programming spec 0003](docs/specs/features/002-programming/specs/0003-playback-ordering.md).                                                                                                                                                                           | rewind, restart (for this)        |
| **Fresh rebuild**          | The owner's explicit **Stop it now and rebuild the schedule**: interrupts the airing entry and regenerates from now with new rounds, marathon decisions, and member positions, keeping collection progress, ended entries, and configuration. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                                                | reset, reshuffle                  |
| **Interruption**           | The owner's explicit choice to end the airing playout item early: now, through a fresh rebuild or catalog removal, or at an interrupting reservation's start, now or later. kraziTV never interrupts on its own. See [ADR 0003](docs/adrs/0003-materialized-schedule-entries.md) and [ADR 0015](docs/adrs/0015-scheduled-interruption.md).                                                                                                                             | preemption, cut-in                |
| **Cut**                    | Where an interrupting reservation ends the playout item airing at its start, or where a running reservation ended early ends its own airing program. Derived from the reservation in the same snapshot as filler, so withdrawing the reservation before the cut restores the item's full airtime; only deleting the reservation after the cut aired writes it into the entry. Code name `cutAtReservations`. See [ADR 0015](docs/adrs/0015-scheduled-interruption.md). | truncation, split                 |
| **Rebuild count**          | A per-channel counter a fresh rebuild advances once per idempotency key. Every kraziPlan decision seed includes it, and a checkpoint made under an earlier count starts a new slate. Stored as `rebuild_count`.                                                                                                                                                                                                                                                        | rebuild version                   |
| **Playout timeline**       | Everything a channel actually transmits, derived from schedule entries and reservations: programs and filler.                                                                                                                                                                                                                                                                                                                                                          | schedule, playlist                |
| **Playout item**           | One thing on the playout timeline: a program, derived from one schedule entry, or a filler interval, derived from entries and reservations. Derived on demand and never persisted.                                                                                                                                                                                                                                                                                     | clip, segment                     |
| **Playout cursor**         | What a channel stream worker asks for following items after: `{ kind: "program", scheduleEntryId }` or `{ kind: "filler", endsAt }`. A cursor whose entry regeneration deleted, or whose filler no longer ends at that instant, is stale. See [ADR 0014](docs/adrs/0014-planned-filler-coverage.md). Unrelated to playback progress.                                                                                                                                   | playout item ID                   |
| **Channel state**          | The deterministic runtime answer to "what is this channel transmitting right now, and at what offset?" Lets viewers join in progress.                                                                                                                                                                                                                                                                                                                                  | now playing, session state        |
| **Join offset**            | The position inside the current playout item where a newly tuned viewer joins. Stored as `offsetMs`.                                                                                                                                                                                                                                                                                                                                                                   | seek position, resume point       |
| **Filler**                 | Non-guide transmission covering time a reservation explains: before its first program, after its last program up to its end, or across a range none of whose programs fit. Derived, never a schedule entry; transmitted as a black screen reading **Programming resumes at <time>** with silence, and shown as **Off air** in the Program Guide. See [ADR 0014](docs/adrs/0014-planned-filler-coverage.md).                                                            | padding                           |
| **Black tail**             | Black video and silence a signal session emits after a playout item's media ends before its airtime does, so the broadcast signal stays continuous until the boundary. Stored as `blackTailMs`. Unlike filler, it belongs to a program's airtime. See [spec 0006](docs/specs/features/001-mvp/specs/0006-signal-packager.md).                                                                                                                                          | padding, dead air                 |
| **Bumper**                 | A short branded clip marking a transition into or out of a program or break.                                                                                                                                                                                                                                                                                                                                                                                           | intro, sting (unless distinct)    |

## Richer Programming Vocabulary

These terms describe the intended concepts in the programming specs; the existing
playback and scheduling definitions above describe their current contracts. Spec
status and unresolved policy live in the linked documents, not in this glossary.

| Term                              | Definition                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Avoid                                  |
| --------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| **Content metadata**              | Normalized descriptive facts about a media item's content, separate from technical probe facts. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                                                                                                                              | probe metadata (for content facts)     |
| **Metadata match**                | A proposed or accepted association between local media and identified content, with an explainable match decision. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                                                                                                           | identification certainty               |
| **Metadata provenance**           | The source, external identity, and matching evidence supporting content facts, including user corrections. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                                                                                                                   | universal confidence score             |
| **Correction**                    | The owner's value for one content fact (title, series, season, episode, or release year) that wins over the provider's until cleared; scans, retries, and refreshes never change it. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                                         | override, manual edit                  |
| **Path hint**                     | A series, title, year, country tag, season, episode, or disc-track value read from a media item's filename and parent folders. Evidence for matching, never accepted content metadata. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                                       | filename guess, parsed metadata        |
| **Series folder**                 | The outermost folder below a media root that names something, holding a show's season folders however they are named. It names the series and gives its year and country tag for every episode beneath it, and one choice resolves all of them. See [ADR 0017](docs/adrs/0017-series-folder-and-folder-evidence.md).                                                                                                                                                                                                                                                             | show folder, nearest folder            |
| **Unlisted episode**              | An episode file matched to a series whose TMDB season does not list its number, as when TMDB and TVDB count a two-part episode differently. It keeps the file's own season and episode numbers and has no episode title. Shown as `Matched; episode not listed on TMDB`. See [ADR 0017](docs/adrs/0017-series-folder-and-folder-evidence.md).                                                                                                                                                                                                                                    | missing episode, unmatched episode     |
| **Extra**                         | A media item under an extras folder such as `Featurettes` or `Deleted Scenes`, or a disc track the owner skipped when mapping tracks: bonus material that is never matched as an episode or movie. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md).                                                                                                                                                                                                                                                                           | bonus feature, special (for this)      |
| **Collection recommendation**     | A proposed media collection whose creation requires explicit user acceptance. See [programming spec 0002](docs/specs/features/002-programming/specs/0002-automatic-collections.md).                                                                                                                                                                                                                                                                                                                                                                                              | automatically created collection       |
| **Programming source assignment** | Enduring channel configuration assigning one or more members (collections or single media items), playback mode, saved assignment order, ordinary stretch setting, and optional marathon setting for kraziPlan to generate blocks, plus an optional owner-given name that programming never reads. My Channels labels each a **Show**, one with several members a **Wheel** (after broadcast wheel series), and lists a channel's on its **Lineup** tab; code and docs say assignment. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md). | programming block (for the assignment) |
| **Airtime target**                | An approximate duration for a source's programming stretch, satisfied by whole programs rather than an exact clock boundary. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                                                                                                                                                                                                                                                                           | strict quota                           |
| **Shuffled round**                | One pass through eligible programming source assignments in deterministically shuffled order, with one turn per usable source. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                                                                                                                                                                                                                                                                         | random source selection                |
| **Stretch setting**               | An assignment's configured fixed airtime target, fixed program count, or variable airtime range, resolved once for a programming turn. My Channels labels the ordinary one **Plays at a time**. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                                                                                                                                                                                                        | exact block duration                   |
| **Content kind**                  | What a set of assignment members plays, as the stretch suggestion classifies their `content_type`: `movies`, `episodes`, or null when mixed or unclassified. It words per-sitting presets and never decides scheduling. Code name `contentKind`. See [programming spec 0008](docs/specs/features/002-programming/specs/0008-channel-setup-ux.md).                                                                                                                                                                                                                                | content type (for this), media type    |
| **Marathon**                      | An optional longer source turn that preserves playback mode and collection progress, then yields to the next pending source. My Channels says a show with a marathon stretch setting **Allows marathons**, and labels the channel's marathon chance and cooldown **Marathons**. See [programming spec 0004](docs/specs/features/002-programming/specs/0004-kraziplan.md).                                                                                                                                                                                                        | extra rotation turn                    |
| **Programming rule**              | Recurring configuration governing source selection under calendar conditions and explicit precedence. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md).                                                                                                                                                                                                                                                                                                                                                                | programming block (for the rule)       |
| **Active rules**                  | The applicable programming rules at the highest priority that has one with a usable source; they program an instant together, and a higher priority takes over completely. The first active rule naming a source supplies its settings and is recorded under the legacy code name `winningRuleId`. See [programming spec 0009](docs/specs/features/002-programming/specs/0009-combined-programming-rules.md).                                                                                                                                                                    | winning rule, winner                   |
| **Programming timezone**          | The server-wide timezone used to evaluate local calendar conditions, configured or else detected from the host; schedule instants remain UTC. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md).                                                                                                                                                                                                                                                                                                                        | browser timezone (for rule decisions)  |
| **Join rule**                     | A programming rule whose sources take turns alongside whatever is playing while it is active: the default lineup, or the active feature rules' sources. Code `behavior: "join"`. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md) and [programming spec 0009](docs/specs/features/002-programming/specs/0009-combined-programming-rules.md).                                                                                                                                                                           | additive rule                          |
| **Feature rule**                  | A programming rule that replaces the default lineup while it is active: the active rules' sources alone take turns, in a rotation context named for the active feature rules. Code `behavior: "feature"`. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md) and [programming spec 0009](docs/specs/features/002-programming/specs/0009-combined-programming-rules.md).                                                                                                                                                  | takeover rule                          |
| **Rule-only assignment**          | A programming source assignment kept out of normal rotation that airs only while an active rule selects it. Code `participation: "rule_only"`. See [programming spec 0005](docs/specs/features/002-programming/specs/0005-recurring-programming-rules.md).                                                                                                                                                                                                                                                                                                                       | seasonal assignment, hidden assignment |
| **Rotation context**              | One independent round continuation: `default`, which join rules share, or `rule:` and the sorted IDs of the active feature rules joined by `+`, so a lone feature rule keeps `rule:<id>`. Member positions and marathon cooldown stay channel-wide. Code `activeContext`, `context_key`. See [programming spec 0009](docs/specs/features/002-programming/specs/0009-combined-programming-rules.md).                                                                                                                                                                              | rotation slot                          |
| **Reserved time range**           | A half-open UTC interval protected for clock-anchored or published manual programming. See [programming spec 0006](docs/specs/features/002-programming/specs/0006-clock-anchored-blocks.md).                                                                                                                                                                                                                                                                                                                                                                                     | soft time window                       |
| **Reservation**                   | A stored reserved time range on one channel with what airs in it: an ordered list of media items or one collection in one playback mode, and an explicit or program-derived end. Ordinary programming stops whole before it. My Channels labels it a **Special**; code and docs say reservation. Code name `Reservation`. See [programming spec 0006](docs/specs/features/002-programming/specs/0006-clock-anchored-blocks.md).                                                                                                                                                  | clock block, anchor, booking           |
| **Resume time**                   | When guide-visible programming next starts after a filler interval, which is the filler's end, shown in the programming timezone in 12-hour form. See [ADR 0014](docs/adrs/0014-planned-filler-coverage.md).                                                                                                                                                                                                                                                                                                                                                                     | return time                            |
| **Programming override**          | Deliberately published programming taking precedence over generated blocks in a reserved range while enduring configuration remains intact. See [programming spec 0007](docs/specs/features/002-programming/specs/0007-manual-programming.md).                                                                                                                                                                                                                                                                                                                                   | replacement channel strategy           |

## Web Administration

| Term                | Definition                                                                                                                                                                                                                                                                                 | Avoid                      |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------- |
| **Desktop shell**   | The browser presentation environment containing shortcuts, windows, Start, taskbar and system tray. Its state is transient and never decides broadcast behavior. See [spec 0008](docs/specs/features/001-mvp/specs/0008-web-admin.md).                                                     | operating-system framework |
| **Desktop program** | A singleton administration interface opened through the desktop or Start, such as My Channels or Media Library.                                                                                                                                                                            | fake process               |
| **Window dialog**   | A dialog owned by one desktop program's window: it covers and blocks only that window's content and cannot leave it. Code name `WindowDialog`.                                                                                                                                             | modal, popup               |
| **Cleanup retry**   | A browser-held reference to a failed administrative runtime stop, retained until the server confirms cleanup succeeded. It never recreates deleted channel configuration.                                                                                                                  | rollback                   |
| **Tray balloon**    | A notification that pops up from a system tray icon, as XP's did. It never blocks a window, and whether it shows again is desktop shell state kept in the browser. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md#tmdb-setup-reminder). | toast, popup, modal        |

| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- |

## Media Catalog

| Term                     | Definition                                                                                                                                                                                                                                                                                                                                                      | Avoid                                                                    |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| **Media root**           | A registered filesystem location that is scanned for media. Answers "where is media?" See [ADR 0006](docs/adrs/0006-media-roots-and-collections.md).                                                                                                                                                                                                            | library, folder, source                                                  |
| **Media collection**     | An explicitly ordered set of media items that programming blocks draw from. Answers "what can be selected?" See [ADR 0006](docs/adrs/0006-media-roots-and-collections.md).                                                                                                                                                                                      | playlist, library                                                        |
| **Manual collection**    | A media collection whose membership and order change only when the user edits them, apart from catalog removal. Code name `maintenanceMode: "manual"`. See [programming spec 0002](docs/specs/features/002-programming/specs/0002-automatic-collections.md).                                                                                                    | static collection, playlist                                              |
| **Automatic collection** | A media collection whose membership kraziTV derives from catalog metadata, such as every episode of one series. Consumed the same way as a manual collection. See the [programming feature](docs/specs/features/002-programming/README.md).                                                                                                                     | smart playlist, auto playlist                                            |
| **Collection criterion** | The one saved rule an automatic collection matches on: a TMDB series, a franchise, a tag, or a genre. Its canonical JSON is also a collection recommendation's identity. Programming never reads it. See [programming spec 0002](docs/specs/features/002-programming/specs/0002-automatic-collections.md).                                                      | rule, filter, query, smart criteria                                      |
| **Collection exclusion** | A durable user decision preventing one media item from joining one automatic collection until restored, even when it matches the criterion. See [programming spec 0002](docs/specs/features/002-programming/specs/0002-automatic-collections.md).                                                                                                               | catalog removal (for exclusion), rejected metadata match (for exclusion) |
| **Tag**                  | A name the owner gives media items, such as `Christmas`, with an identity independent of its spelling: names that differ only in case are one tag. Tagging an episode never tags its siblings, and adding a tag never creates a collection. See [programming spec 0002](docs/specs/features/002-programming/specs/0002-automatic-collections.md).               | label, theme (for a user tag), keyword                                   |
| **Media item**           | One cataloged file, identified by its media root and normalized absolute path. Status is `available`, `missing`, or `probe_failed`.                                                                                                                                                                                                                             | asset, file record, video                                                |
| **Catalog**              | The persisted inventory of media roots and media items.                                                                                                                                                                                                                                                                                                         | database, index                                                          |
| **Catalog scan**         | One discover → probe → validate → persist pass over a media root. Commits atomically; a failed scan leaves prior statuses untouched.                                                                                                                                                                                                                            | import, sync, refresh                                                    |
| **Scan job**             | The server's in-memory record of one catalog scan, or one lookup retry, of one media root: its phase, progress counts, and outcome. At most one runs per root. See [spec 0009](docs/specs/features/001-mvp/specs/0009-background-catalog-scans.md).                                                                                                             | background task, scan session                                            |
| **Lookup retry**         | A scan job of kind `retry` that looks up one item, the folder holding it, or a root's failed lookups on TMDB again, running only `enriching -> committing`. It never probes and never changes corrections or extras. See [programming spec 0001](docs/specs/features/002-programming/specs/0001-metadata-enrichment.md#scan-progress-retry-and-refresh).        | rescan, re-enrich                                                        |
| **Catalog removal**      | A user's deliberate removal of a media root or media items from the catalog. Removed media leaves every list, collection, and future schedule at once. Unlike `missing`, it is a user action, not a scan result. The Media Library labels it **Delete**; code and docs say removal. See [spec 0010](docs/specs/features/001-mvp/specs/0010-catalog-removal.md). | delete (outside UI labels)                                               |
| **Purge**                | Deleting a removed media item's row and its ended schedule entries, and its media root once empty, after no airing entry still holds the item. See [spec 0010](docs/specs/features/001-mvp/specs/0010-catalog-removal.md).                                                                                                                                      | cleanup, garbage collection                                              |
| **Probe**                | Running ffprobe against a file to read duration, streams, and codecs. A probe failure is stored, not thrown away.                                                                                                                                                                                                                                               | analyze, inspect                                                         |

## Broadcast And Provider Terms

Industry terms kraziTV relies on. Use them with these meanings.

| Term                    | Definition                                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| **Linear TV**           | Programming that airs on a fixed timeline regardless of when a viewer tunes in. The behavior kraziTV simulates.                                |
| **Wall-clock time**     | Real UTC time. Channels advance at wall-clock speed whether or not anyone is watching. kraziTV stores time as integer milliseconds (ADR 0007). |
| **Broadcast signal**    | The single continuous encoded output of one active channel, shared by all of its viewers.                                                      |
| **Backpressure**        | A slow consumer pushing back on a producer. A viewer's backpressure must never slow a channel's broadcast signal.                              |
| **Tune**                | A viewer's client requesting a channel's stream. Tuning subscribes to the shared broadcast signal.                                             |
| **Subscriber**          | A viewer connection currently receiving a channel's broadcast signal.                                                                          |
| **Idle grace period**   | How long a channel stream worker keeps running after its last subscriber disconnects.                                                          |
| **EPG / guide data**    | Electronic program guide: the schedule as a client displays it.                                                                                |
| **XMLTV**               | The XML guide-data format kraziTV emits for Plex and other clients.                                                                            |
| **M3U**                 | A plain playlist of channel stream URLs, used by generic IPTV clients and for debugging.                                                       |
| **HDHomeRun emulation** | Exposing HDHomeRun-compatible discovery, device, status, and lineup endpoints so Plex treats kraziTV as a network tuner (ADR 0002).            |
| **Lineup**              | The list of channels a tuner advertises to a client. Unrelated to My Channels' **Lineup** tab, a channel's programming source assignments.     |
| **MPEG-TS**             | MPEG transport stream, the container kraziTV broadcasts. Designed for continuous streams that clients can join mid-flow.                       |
| **Transcode / remux**   | Transcoding re-encodes media; remuxing changes only the container. SignalPackager chooses between them, never kraziBrain.                      |
